# Новая работа Пульса

Одна работа — один постер на своей странице `/work/<slug>/`. Реальные данные становятся цветом, формой и скоростью. Цикл рассчитан на выпуск раз в пару дней, поэтому от автора нужны только два решения: выбрать концепцию и принять готовую работу. Всё остальное решай сам и сообщай итогом.

Прочитай `docs/studio.md`: там контракт работы и устройство проекта. Общайся по-русски.

## 1. Разбор заявки

Определи тип входа и что из него следует:

| Вход | Что делать |
|---|---|
| API или ссылка | Сразу к проверке источника, тему вывести из данных |
| Тема или идея | Найти 2–3 открытых источника, взять лучший по шагу 2 |
| Изображение | Взять настроение, композиционный приём и палитру, потом найти подходящие данные |
| Датасет или файл | Статичная работа: данные в `src/data/`, движение из проигрывания во времени |

Изображение чужого автора — это настроение, а не образец для копирования: работа должна быть самостоятельной, без повторения композиции конкретного произведения, логотипов и имён.

Задавай вопросы только если ответ меняет работу, не больше трёх за раз, с вариантом по умолчанию:
1. Что зритель должен почувствовать или заметить за три секунды?
2. Что меняет кнопка «Случайно»?
3. Какая главная величина, если в данных их несколько?

Если автор написал «делай» или ответ очевиден из заявки, не спрашивай.

## 2. Проверка источника

Проверяй до рисования, потому что смена источника потом переделывает работу. Из этой сети обязательно без прокси: в окружении бывает `HTTPS_PROXY` с выходом в Нидерланды, и через него заблокированный источник выглядит живым.

```sh
curl -s --noproxy '*' -m 15 -A puls-stand -H 'Origin: http://localhost:5173' -D - -o body.json '<url>'
```

Смотри на полное тело, а не на код ответа: бывают обрывы на 200. Зафиксируй: разбирается ли JSON целиком, есть ли CORS (без него нужен маршрут в `vite.config.ts`), нужен ли ключ, какой лимит запросов, как часто данные меняются, можно ли их показывать и как подписывать.

Ключи не попадают в браузерный код: только через маршрут Vite и `.env`. Посты людей, личные данные и немодерируемый текст на постер не выводи, только агрегаты. Если источник не годится, предложи замену, а не обходной путь.

## 3. Концепция — первое решение автора

Предложи три разные концепции, каждая в три строки: образ, что кодирует положение, что происходит за 30 секунд. Сверься с формами в `releases/forms.md`: новая работа не должна повторять приём предыдущих. Рекомендуй одну и скажи почему. Жди выбор.

## 4. Кодировка

Составь таблицу «величина → канал → почему». Пульс — искусство, а не аналитика: данные настоящие и управляют картинкой, но оценки и упрощения допустимы, а при споре красоты и точности побеждает красота. Правила ниже пришли из аудита постеров и помогают сделать работу интереснее, это не закон:

- Главная величина занимает положение на листе: его глаз считывает точнее всего. Цвет и площадь — для второстепенного.
- Площадь пропорциональна значению: радиус через корень, без скрытой базы.
- Шкала не обманывает настроением: мелкое движение не должно выглядеть катастрофой, если это не задумка работы.
- Значимы все приёмы. Случайный поворот или разброс заставляет зрителя искать смысл там, где его нет.
- Разные смыслы выглядят по-разному: две похожие точки с разным значением неразличимы.
- Цвета одной категории проверяй валидатором из скилла `dataviz`: разница ΔE не меньше 15.
- Счётное показывай счётным: точка — гол, искра — пост.
- Скорость настоящая или честно описанная, переходы плавные через `glide`.
- На листе нет осей, легенд и графиков; числа только в подписи и экспликации.

## 5. Сборка

1. Скопируй `.claude/skills/new-work/assets/poster.ts` в `src/channels/<slug>.ts`.
2. Добавь запись в `WORKS` в `src/works.ts`: следующий номер, дата выпуска. Новая работа сама попадает в раздел «Идеи».
3. При необходимости маршрут в `vite.config.ts`, варианты в `src/config.ts`.
4. Разбор данных и математику вынеси в чистые функции и покрой тестами в `tests/channels.test.ts`, используя реальный ответ источника.
5. Заведи `releases/<slug>/brief.md` по шаблону из `docs/studio.md`.
6. Все тексты пиши на двух языках через `tr('…', '…')` из `src/lib/i18n.ts`. Если показываешь место с координатами, реализуй `where()`.

Посмотри на соседние работы, прежде чем писать: новый код должен читаться как они.

## 6. Проверка

Сервер запускай без прокси:

```sh
env -u HTTPS_PROXY -u HTTP_PROXY -u ALL_PROXY -u https_proxy -u http_proxy -u all_proxy npx vite --port 5173 --strictPort
npm run shot -- <slug>
npm test && npm run build
```

`shot` проверяет эфир, движение, частоту кадров, экспликацию на 1280×720, телефон и снимает превью. Автоматика не видит искусство, поэтому обязательно открой кадры и ответь себе:

- Подмени данные случайными: зритель заметит? Если нет, данные не работают.
- Смотрится ли постер рядом с остальными на главной?
- Что интересного случится за 30 секунд?
- Как выглядит крайний случай: пусто, очень много, один элемент, нет связи? Без данных показывай пустой лист, а не выдумку.
- Работает ли «Случайно» несколько раз подряд?

Что нашёл, исправь до показа автору.

## 7. Показ — второе решение автора

Если есть интересные идеи, собери сразу несколько живых вариантов, обычно 2–3: автору легче выбирать между работающими картинками, чем между описаниями. На одной из работ он предпочёл вариант, который я считал слабее, и понял это только сравнив оба вживую. Варианты должны отличаться характером, а не оттенками: плотность, композиция, ритм, палитра.

Вариант живёт в том же файле работы и выбирается адресом:

```ts
const LOOK = globalThis.location?.search.match(/look=(\w+)/)?.[1] ?? 'a';
```

Дай ссылки `/work/<slug>/?look=a`, `?look=b` и по строке о характере каждого, скажи, какой нравится тебе и почему. После выбора удали остальные варианты и `LOOK` из кода, сними превью заново.

Если сильная идея одна, не выдумывай варианты ради числа: покажи её. Вместе с вариантами дай одну строку о том, что в работе слабее всего как в картине. Если правок нет, выпускай. Больше двух кругов правок — повод вернуться к концепции, а не шлифовать.

## 8. Выпуск

- Статус «Готово к публикации» ставит автор кнопкой в мастерской. Если он сказал об этом тебе, поставь `ready` в `src/works-stages.json`.
- `releases/forms.md`: добавь строку о форме работы.
- `releases/<slug>/post.md`: текст анонса, 2–3 предложения и ссылка.
- `README.md`: строка в таблице работ.
- Убери идею из `releases/backlog.md`, если она оттуда.
- Коммит и публикацию делай только когда автор попросил.

Итог автору: адрес, что кодирует работа, что проверено. Мелкие погрешности данных не перечисляй.
